# План улучшения и переработки Dashboard

> **Design-подход**: план дополнен рекомендациями из skill `frontend-design` — выбор эстетики, типографика, motion, композиция. См. разделы 2.1 и 2.2.

## 1. Текущее состояние (анализ)

### Что есть сейчас
- **Приветствие** — «Привет, username!» + подзаголовок
- **4 карточки статистики** (кликабельные): Servers, Tasks, Agents, Workflows
- **Quick Actions** — сетка кнопок: Run Agent, New Task, Add Server, Chat, Knowledge Base, Passwords, IDE, Orchestrator, Skills
- **Мои задачи** — последние 5 задач (если `user_can_tasks`)
- **Недавние проекты** — 3 проекта (если `user_can_tasks`)
- **Recent Agent Runs** — 5 последних запусков агентов
- **System Status** — API, DB, RAG, MCP + версия приложения
- **Обновление статистики** — каждые 30 сек через `/api/dashboard/stats/`

### Проблемы
1. **Смешение языков** — часть на русском, часть на английском
2. **Нет иерархии** — всё в одной плоскости, непонятно, с чего начать
3. **Дублирование** — Quick Actions частично дублируют sidebar
4. **Нет контекста** — не видно «что требует внимания» (срочные задачи, ошибки, предупреждения)
5. **Слабая навигация** — переходы есть, но нет «путей» (например: задача → чат с контекстом)
6. **Неиспользуемые данные** — `unread_notifications_count` есть в контексте, но не отображается
7. **Нет персонализации** — одинаковый вид для всех ролей
8. **Нет «Getting Started»** — новый пользователь не понимает, что делать первым
9. **Отсутствуют полезные виджеты** — диск, Jira, последние чаты, избранные серверы

## 2. Цели и принципы

### Цели
- **Удобство** — пользователь быстро находит нужное и понимает, куда идти
- **Понятность** — чёткая структура, единый язык (русский)
- **Функциональность** — полезные действия в 1–2 клика
- **Контекст** — видно, что требует внимания (задачи, ошибки, уведомления)

### Принципы
- **Приоритет по ролям** — показывать только то, к чему есть доступ
- **Минимум дублирования** — Quick Actions как «горячие» действия, не копия меню
- **Плавные переходы** — анимации, breadcrumbs, понятные ссылки

---

## 2.1 Design Direction (frontend-design)

**Purpose**: Dashboard для DevOps/IT — оперативный обзор системы, быстрый доступ к задачам, агентам, серверам. Аудитория: технические специалисты, админы.

**Tone**: Выбрать чёткое направление и держаться его:
- **Вариант A**: Industrial/utilitarian — строгий, функциональный, «инструмент», минимум декора
- **Вариант B**: Refined minimal — элегантный, сдержанный, много воздуха, точная типографика
- **Вариант C**: Tech/terminal — тёмная тема, монохром с акцентами, «командный центр»

**Differentiation**: Один запоминающийся элемент — например, живой статус-индикатор, необычная композиция Hero, или характерная анимация появления карточек.

**CRITICAL**: Избегать generic AI-эстетики: Inter/Roboto/Arial, фиолетовые градиенты на белом, предсказуемые сетки. Делать осознанный выбор и выполнять его последовательно.

## 2.2 Frontend Design Guidelines

### Typography
- [ ] **Не использовать** Inter, Roboto, Arial, system fonts — они дают «AI slop» вид
- [ ] Подобрать **характерный** display-шрифт для заголовков + **читаемый** body-шрифт
- [ ] Примеры: Geist, Satoshi, Cabinet Grotesk, DM Sans, Source Sans 3, IBM Plex Sans
- [ ] Чёткая иерархия: размер, вес, цвет — заголовки vs подзаголовки vs body

### Color & Theme
- [ ] **Доминирующий цвет** + **острые акценты** — лучше, чем равномерная палитра
- [ ] CSS-переменные для консистентности (уже есть в `style.css`)
- [ ] Тёмная тема: глубокий фон, приглушённые поверхности, яркий accent для CTA
- [ ] Семантика: success/warning/error — не смешивать с primary

### Motion
- [ ] **Один сильный момент** — например, staggered reveal при загрузке (animation-delay)
- [ ] Hover-состояния с неожиданностью: лёгкий lift, glow, scale
- [ ] Приоритет CSS-only анимаций (performance)
- [ ] Не разбрасывать микро-интеракции — лучше один продуманный flow

### Spatial Composition
- [ ] **Неожиданная композиция**: асимметрия, overlap, grid-breaking
- [ ] Либо **щедрый negative space**, либо **контролируемая плотность**
- [ ] Hero-блок может выходить за пределы сетки, диагональный акцент
- [ ] Карточки — не обязательно одинаковый размер; «главная» карточка может быть крупнее

### Backgrounds & Visual Details
- [ ] **Глубина и атмосфера** вместо плоских solid-цветов
- [ ] Варианты: gradient mesh, noise texture, geometric pattern, layered transparency
- [ ] Тени: dramatic shadows для карточек при hover
- [ ] Grain overlay для тактильности (если подходит tone)

## 3. Фазы реализации

**Рекомендуемый порядок**: сначала Design Direction (2.1) + выбор Typography/Color (2.2), затем Фаза 1. Эстетика задаёт тон всем последующим изменениям.

### Фаза 1: Базовая переработка (приоритет: высокий)

#### 1.1 Единый язык
- [ ] Перевести все надписи на русский (или сделать конфигурируемым)
- [ ] Унифицировать термины: «Агенты», «Задачи», «Серверы», «Воркфлоу» и т.д.

#### 1.2 Структура и навигация
- [ ] **Hero-блок** — приветствие + краткий статус («Всё в порядке» / «Требует внимания: X задач, Y ошибок»)
- [ ] **Быстрые переходы** — горизонтальная полоса «Куда идти»:
  - Задачи → `/tasks/`
  - Агенты → `/agents/`
  - Серверы → `/servers/`
  - Монитор → `/monitor/`
  - Чат → `/chat/`
- [ ] **Breadcrumbs** — расширить: Home / Dashboard (или Home / Раздел при переходе)

#### 1.3 Карточки статистики
- [ ] Сохранить 4 карточки, но улучшить:
  - Добавить **иконку статуса** (например, предупреждение при 0 активных серверов)
  - **Вторичный CTA** — «Добавить сервер» при 0 серверов
  [ ] Сделать карточки более информативными: тренд (↑/↓), мини-график (опционально)

#### 1.4 Quick Actions — переосмысление
- [ ] Группировать по смыслу:
  - **Работа**: Запустить агента, Новая задача, AI Чат
  - **Инфраструктура**: Добавить сервер, Пароли
  - **Настройки**: Knowledge Base, IDE, Orchestrator, Skills
- [ ] Убрать дублирование с sidebar — оставить только «горячие» действия
- [ ] Добавить **контекстные действия** (например, «Запустить воркфлоу» при наличии workflow)

- [ ] **Для settings** — «Диск» (место на диске) — API `/api/disk/` уже есть

#### 2.3 Недавние чаты

### Фаза 3: Расширенная функциональность (приоритет: средний)

#### 3.1 Виджет «Место на диске»
- [ ] Для `user_can_settings` — компактная карточка с путями (корень, MEDIA, AGENT_PROJECTS)
- [ ] Предупреждение при заполнении > 85%

#### 3.2 Виджет «Избранные серверы»
- [ ] Топ-3 сервера пользователя (по последнему использованию или вручную)
- [ ] Быстрая команда: «Подключиться» / «Выполнить команду»

#### 3.3 Связки переходов (workflow-навигация)
- [ ] **Задача → Чат**: кнопка «Обсудить с AI» на карточке задачи → `/chat/?task_id=X`
- [ ] **Запуск → Monitor**: клик по run → `/monitor/?run_id=X` (уже есть)
- [ ] **Проект → Задачи**: клик по проекту → `/tasks/projects/<id>/`

#### 3.4 Jira-интеграция (если включена)
- [ ] Мини-виджет: последние синхронизированные задачи или статус синка
- [ ] Ссылка на настройки Jira

---

### Фаза 4: UX и полировка (приоритет: средний)

#### 4.1 Анимации и переходы (frontend-design: Motion)
- [ ] **Staggered reveal** при загрузке — один продуманный момент (animation-delay по карточкам)
- [ ] Hover: lift + subtle shadow или glow — не generic, а осмысленный feedback
- [ ] Skeleton loading при первой загрузке статистики
- [ ] Плавный скролл при переходе к секции (если длинная страница)

#### 4.2 «Getting Started» для новых пользователей
- [ ] При первом входе (или пустом состоянии) — блок «Начните с»:
  - Добавьте сервер
  - Создайте задачу
  - Запустите агента
  - Откройте чат
- [ ] Ссылка на Onboarding Tour (уже есть в Help)

#### 4.3 Единообразие и визуальная система
- [ ] Все карточки в одном стиле (`.dashboard-card`) с возможностью варьировать размер
- [ ] Иконки: Material Icons Round — ок, но рассмотреть альтернативу (Lucide, Phosphor) для уникальности
- [ ] Единые отступы и радиусы (tokens из style.css)
- [ ] **Typography**: применить выбранный display + body font (см. 2.2)
