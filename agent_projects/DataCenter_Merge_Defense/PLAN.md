# План: DataCenter Merge Defense

**Платформа:** Yandex Games  
**Жанр:** Merge Tower Defense + Roguelite  
**Рантайм:** ralph  
**Цель:** браузерная игра с короткими сессиями (2–5 мин), прогрессом, ежедневными челленджами, лидербордами и монетизацией через SDK.

---

## Концепция

- **Питч:** Собирай и сливай «серверы» в дата-центре, отбивай волны вирусов/пакетов. Между волнами — выбор roguelite-карт. Короткие забеги, мета-прогресс, ежедневный режим с общим лидербордом.
- **Сессия:** 2–5 мин, one-handed + мышь, мягкая кривая сложности.
- **Стек:** Phaser 3, TypeScript, Vite; данные из JSON; сохранение — Yandex Player data + fallback localStorage.

## Детализация шагов

### 1. Рынок + продуктовые ограничения + дизайн-спека на 1 страницу — ✅ Выполнено

- **Результат:** `DESIGN_SPEC.md` в корне, `game_config.json` и конфиги в `public/configs/` (turrets, enemies, cards, waves).
- **Проверка:** Спека есть, ограничения платформы перечислены, MVP не раздут.

---

### 2. Скелет проекта + рендер + адаптивный canvas — ✅ Выполнено

- **Результат:** Vite + TypeScript + Phaser 3, сцены Boot → Menu → Run, кнопка «Играть», пустая сетка и базовый loop в Run.
- **Проверка:** Сборка работает, canvas адаптируется, страница без скролла.

---

### 3. Архитектура состояния и data-driven конфиги — ✅ Выполнено

- **Результат:** GameState (runState, metaState), загрузка турелей/врагов/карт/волн из JSON, валидация конфигов (`configValidation.ts`).
- **Проверка:** Баланс меняется правкой JSON, при ошибке конфига — понятное сообщение.

---

### 4. Поле-сетка + drag&drop + merge механика (MVP) — ✅ Выполнено

- **Результат:** Сетка 5×6 / 6×7 с авто-масштабированием, спавн турели, перетаскивание, merge одинаковых по типу и tier, отображение tier, кнопка «Купить турель».
- **Проверка:** Merge по правилам, перетаскивание не ломает сетку, софтлока нет.

---

### 5. Маршрут врагов + волны — ✅ Выполнено

- **Результат:** Path (клеточный маршрут), генератор волн из конфига, враги с HP и скоростью, снятие жизней при проходе до конца, UI жизней и волны.
- **Проверка:** Волны по расписанию, враги исчезают корректно, поражение при нуле жизней.

---

### 6. Бой: авто-стрельба турелей + базовые роли — ✅ Выполнено

- **Результат:** Прицеливание по ближайшей цели в радиусе, минимум 3 роли (single-target, splash, slow), параметры из конфига, лёгкие эффекты.
- **Проверка:** Турели различаются по поведению, без просадок FPS при 30+ врагах.

---

### 7. Roguelite-карты между волнами — ✅ Выполнено

- **Результат:** После каждой 2-й волны — выбор 1 из 3 карт; карты меняют мультипликаторы (урон, скорострельность, крит, бонус за merge); эффекты только на забег.
- **Проверка:** Выбор влияет на бой, эффекты не переносятся между забегами.

---

### 8. Экономика забега + награды + экран результата — ✅ Выполнено

- **Результат:** Награды за волну/босса (валюта, детали), экран результата (win/lose) со статистикой (волна, время, merges, урон), «Сыграть ещё» и возврат в хаб.
- **Проверка:** Прогресс понятен, награда не теряется при переходах.

---

### 9. Мета-хаб: апгрейды и анлоки — ✅ Выполнено

- **Результат:** Добавлен Meta Hub в `MenuScene` с data-driven деревом из 11 апгрейдов и анлоками турелей. Реализованы ежедневные задания (3 ротационных из пула), прогресс, клейм наград, хранение в `metaState` и `public/configs/meta.json`.
- **Проверка:** Апгрейды влияют на стартовые кредиты/жизни, шанс редкой турели, множитель наград и доступные турели в забеге; daily-задания пересоздаются раз в сутки по локальному времени и сохраняются между перезапусками.

---

### 10. Интеграция Yandex Games SDK: init + ready + пауза/звук — ✅ Выполнено

- **Результат:** Добавлен SDK-слой `src/sdk/yandexGamesSdk.ts` с `YaGames.init()` и fallback в гостевой режим, подключён `/sdk.js` в `index.html`, вызов `LoadingAPI.ready()` перенесён в `MenuScene` при готовности кнопки запуска. Реализованы сигналы `game_api_pause/resume` и browser `blur/focus/visibilitychange` для паузы забега и mute звука.
- **Проверка:** Игра запускается и без авторизации (guest fallback), ready вызывается один раз при готовности меню, при сворачивании/потере фокуса звук мьютится и забег ставится на паузу, при возврате корректно возобновляется без ломания логики волн.

---

### 11. Сохранения: cloud (Player data) + fallback localStorage — ✅ Выполнено

- **Результат:** Добавлен профиль сохранения (`metaState + settingsState`) в `src/game/saveSystem.ts` с cloud key через Yandex Player data и fallback в localStorage, с debounce/очередью для частых изменений и flush при выходе из забега. На старте реализован выбор «Продолжить» / «Новая игра» в `MenuScene` при наличии профиля.
- **Проверка:** После перезапуска профиль загружается из cloud, а при недоступном cloud берётся local fallback; частые обновления не создают фризов за счёт debounce и сериализации сохранений; при выборе «Новая игра» профиль сбрасывается и пересоздаётся.

---

### 12. Монетизация: rewarded/interstitial/sticky по правилам пауз — ✅ Выполнено

- **Результат:** Добавлен слой монетизации `src/game/monetization.ts` и расширение SDK-обёртки (`showRewardedVideo`, `showFullscreenAdv`, `showBannerAdv/hideBannerAdv`). Sticky включается только в хабе (`MenuScene`) и отключается в бою (`RunScene`). Rewarded реализован на экране результата как «Удвоить бонус (Ad)». Interstitial показывается только после забега (при выходе в хаб/рестарте) с лимитом 1 показ на 2 забега.
- **Проверка:** Interstitial не вызывается в бою; rewarded начисляет заявленное удвоение бонуса; sticky не показывается в RunScene и включается только в меню/хабе.

---

### 13. Платежи (IAP): no_ads и starter_pack — ✅ Выполнено

- **Результат:** Добавлен IAP-слой `src/game/iap.ts` и расширен SDK-адаптер платежей (`getPayments`, каталог, покупка, список покупок, consume). В хабе реализован IAP Store (модальное окно) с ценами из каталога для `no_ads` и `starter_pack`. `no_ads` сохраняется в `settingsState` и отключает interstitial/sticky; `starter_pack` является consumable и начисляет Meta Credits с consume токена покупки.
- **Проверка:** no_ads переживает перезапуск (через cloud/local save), starter_pack начисляется на каждую подтверждённую покупку и сразу потребляется; при отсутствии SDK покупки недоступны, но игра работает в guest/fallback режиме без падений.

---

### 14. Daily Challenge + лидерборд — ✅ Выполнено

- **Результат:** Реализован Daily Challenge режим с запуском из хаба (`MenuScene`), датой дня и фиксированным seed для выбора ежедневных карт. Добавлен расчёт daily score (волна + merges + урон − время), отправка в leaderboard через SDK только при улучшении результата, и отображение топа/позиции игрока в хабе. Добавлен модуль `src/game/dailyChallenge.ts` и расширен SDK-адаптер для leaderboard API.
- **Проверка:** Для одной даты daily-выбор карт детерминирован, leaderboard грузится в хабе (топ + player entry), отправка ограничена (cooldown + только лучший score), что исключает спам.

### 15. Онбординг и UX-полировка — ✅ Выполнено

- **Результат:** Добавлен onboarding в первом обычном забеге: пошаговый оверлей `1/3 купить турель → 2/3 drag → 3/3 merge`, с кнопкой «Пропустить» и автозавершением/сохранением статуса. В хабе добавлены UX-подсказки mobile/desktop и панель `Settings` (звук, вибрация, скорость x1/x1.5). Скорость применяется в обычном забеге, а в daily фиксирована x1 для честного лидерборда.
- **Проверка:** В первом запуске игрок получает понятный интерактивный туториал; элементы управления и подсказки читаемы на mobile/desktop; настройки сохраняются в профиль и применяются между сессиями; отключены контекстное меню, выделение текста и drag/select браузера.

- **Проверка:** `npm run build` без ошибок; архив валиден; размер в норме; на мобилке нет WebGL-алертов/скролла; чек-лист закрыт.
