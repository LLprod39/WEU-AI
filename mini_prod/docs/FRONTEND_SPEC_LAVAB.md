# Техническое задание: фронтенд веб-терминала с ИИ

Описание **что должно быть на сайте** (страницы, блоки, элементы, поведение). Визуальный дизайн не задаётся — его создаёт исполнитель/ИИ.

---

## 1. Общее описание продукта

- Веб-приложение: **управление серверами + SSH/RDP терминал в браузере + встроенный ИИ-ассистент в терминале**.
- Пользователь логинится, видит список серверов (с группами), открывает терминал по SSH или RDP. В терминале есть панель чата с ИИ: можно задать вопрос по выводу в терминале, попросить сформировать команду или объяснить результат.
- Бэкенд уже есть: Django + Daphne (ASGI), WebSocket для терминала, REST API для серверов, групп, настроек. Нужен фронтенд, который подключается к этим API и WebSocket. Дизайн — на усмотрение исполнителя.

---

## 2. Стек и ограничения

- **Бэкенд не трогаем**: API и WebSocket URLs должны совпадать с существующими.
- Фронтенд: на выбор — HTML + CSS + JS или SPA (React/Vue/Svelte).
- **Терминал в браузере**: библиотека **xterm.js** для отображения SSH-потока; данные приходят по WebSocket.

---

## 3. Маршруты (страницы)

- **`/login/`** — страница входа (логин, пароль, редирект после успеха).
- **`/`** — редирект: админ → `/dashboard/`, иначе → `/servers/`.
- **`/servers/`** — список серверов и групп, переход в терминал или RDP.
- **`/servers/hub/`** — мульти-терминал: несколько серверов в табах в одном экране.
- **`/servers/<id>/terminal/`** — SSH-терминал с табами и панелью ИИ.
- **`/servers/<id>/terminal/minimal/`** — вариант терминала без основного меню (только терминал и опционально ИИ).
- **RDP**: страница/роут для RDP (например `/servers/<id>/rdp/`) — область вывода удалённого рабочего стола.
- **`/settings/`** — главная настроек: модели ИИ, логи активности, переходы к пользователям/группам/правам.
- **`/settings/access/`**, **`/settings/users/`**, **`/settings/groups/`**, **`/settings/permissions/`** — подстраницы настроек доступа.
- **`/dashboard/`** — дашборд для админов (сводка).
- **`/admin/`** — Django Admin (можно не переделывать).

---

## 4. Общий layout (что есть на каждой странице)

- **Боковое меню (сайдбар)**: логотип/название приложения, пункты — Dashboard, Servers, Settings; внизу — текущий пользователь и выход (Sign Out). Меню можно сворачивать.
- **Основная область**: заголовок страницы с навигационной цепочкой (breadcrumbs: Home / Servers / …), затем контент страницы.
- **Уведомления**: возможность показывать всплывающие сообщения (успех, ошибка, информация).
- **Мобильная версия**: на маленьких экранах меню скрыто по умолчанию, открывается по кнопке; контент занимает всю ширину.

---

## 5. Страница списка серверов (`/servers/`)

- Серверы сгруппированы по **группам**. Группа — секция с заголовком; секции можно сворачивать/разворачивать.
- У каждого сервера отображаются: **название**, **хост** (адрес), **статус** (онлайн / офлайн / неизвестно). Должны быть кнопки или ссылки: **«SSH Terminal»**, **«RDP»** (если для сервера включен RDP), **редактирование/настройки** сервера.
- Вверху страницы: заголовок (например «Infrastructure» или «Servers»), при необходимости — «Добавить сервер», управление группами, фильтры.
- Список/сетка должна нормально работать на мобильных (одна колонка или удобный просмотр).

---

## 6. Страница SSH-терминала (`/servers/<id>/terminal/`)

- **Вкладки (табы) сверху**: одна вкладка = один открытый терминал (сервер). В табе: имя сервера, индикатор состояния подключения (подключен / подключается / ошибка), кнопка закрытия вкладки. Кнопка «+» или «Добавить» — выбор другого сервера и открытие его в новой вкладке.
- **Рабочая зона**: область терминала (xterm.js) и рядом **панель ИИ** (см. п. 7). На узких экранах панель ИИ может быть под терминалом.
- **Тулбар над терминалом**: отображение статуса подключения; кнопки: полноэкран, копировать, вставить, поиск по тексту в терминале, открыть/закрыть панель ИИ; при необходимости — контекстное меню (ПКМ).
- **Учётные данные**: если для подключения нужны логин/пароль — раскрываемая панель с полями логин, пароль и кнопками «Подключить» / «Отключить».
- **Обрыв связи**: при потере соединения — сообщение типа «Connection lost» и кнопка «Reconnect».
- **Терминал (xterm.js)**: вывод текста, курсор, скролл, выделение текста с копированием в буфер обмена; подстройка размера под контейнер при ресайзе окна.

---

## 7. Панель ИИ в терминале

- **Где**: справа от области терминала (на мобильных — снизу). Ширину можно менять (ресайз разделителем).
- **Открытие/закрытие**: кнопка в тулбаре терминала открывает/закрывает панель; когда панель закрыта — доступна небольшая кнопка «ИИ» для открытия.
- **Шапка панели**: заголовок («AI Assistant» или аналог), подзаголовок (модель или статус «Ready»/«Connected»), кнопка свернуть, кнопка остановить генерацию (видна, когда ИИ отвечает).
- **Чат**: сообщения пользователя и ответы ИИ; системные сообщения (ошибки, предупреждения) выделяются отдельно.
- **Ответы ИИ**: поддержка Markdown — заголовки, списки, жирный, код, блоки кода (желательно с подсветкой и кнопкой «Copy»), таблицы.
- **Пустой чат**: приветственный текст и быстрые подсказки (например «Объясни вывод», «Предложи команду», «Проверь синтаксис», «Что означает ошибка»).
- **Ввод**: поле ввода и кнопка «Отправить»; отправка по Enter.
- **Состояния**: индикация «ИИ печатает» (thinking), сообщение об ошибке в чат, кнопка «Stop» во время генерации.
- **Специальные блоки**: если ИИ возвращает «репорт» (команда + результат + статус ok/warning/error) — отобразить структурированно (заголовок, тело, явный статус).

---

## 8. WebSocket для SSH-терминала

- **URL**: `ws://<host>/ws/servers/<server_id>/terminal/` (в продакшене `wss://`).
- Одно WebSocket-соединение на открытую вкладку терминала; обмен в JSON.
- **Клиент → сервер**: ввод с клавиатуры терминала (type: input), при необходимости resize (колонки/строки), запрос к ИИ (type: ai_request, message), остановка ИИ.
- **Сервер → клиент**: вывод для xterm, события ИИ (куски ответа, конец, ошибка, статус «думает»). Формат совместим с бэкендом (consumers.py).
- При закрытии сокета показывать «Connection lost» и дать возможность переподключиться без перезагрузки страницы.

---

## 9. REST API для интеграции

- Авторизация: сессия (cookie) + CSRF-токен в запросах.
- **Серверы**: создание, обновление, тест подключения, удаление, получение одного; список — через контекст шаблона или API, если SPA.
- **Группы**: создание/обновление/удаление групп, добавление/удаление серверов в группу, подписка пользователя на группу.
- **Настройки**: получение/сохранение настроек, список моделей (`/api/models/`), логи активности (`/api/settings/activity/`).
- **Доступ**: API пользователей, групп, прав (`/api/access/users/`, `/api/access/groups/`, `/api/access/permissions/` и т.д.).
- **Логин**: POST `/login/` с полями `username`, `password`, `csrfmiddlewaretoken`; редирект при успехе.

---

## 10. Страница настроек (`/settings/`)

- Блок **«Модели»**: выбор провайдера и модели чата (данные с `/api/models/`), кнопка обновления списка.
- Блок **«Логи активности»**: список/таблица последних действий (данные с `/api/settings/activity/`).
- Ссылки или табы на подстраницы: **Пользователи**, **Группы**, **Права доступа**.
- Формы с кнопками сохранения там, где данные редактируются.

---

## 11. Страница входа (`/login/`)

- Форма: поля **Username**, **Password**, кнопка входа (например «Sign in»).
- Отображение ошибки при неверном логине/пароле (под формой или уведомлением).
- CSRF-токен в форме.

---

## 12. RDP-терминал

- Отдельная страница/вид для RDP: область вывода удалённого рабочего стола (клиент через guacd или аналог), управление полноэкранным режимом и отключением.

---

## 13. Адаптив

- На мобильных: боковое меню скрыто, открывается по кнопке; список серверов — в одну колонку; терминал и панель ИИ — друг под другом (терминал сверху, ИИ снизу), при необходимости с изменяемой высотой панели ИИ.
- Вкладки терминала на мобильных — с горизонтальным скроллом при большом количестве.

---

## 14. Доступность (a11y)

- У интерактивных элементов — подписи или `aria-label`.
- Управление с клавиатуры (Tab, Enter); в модальных окнах — возможность закрытия (Escape).
- Контраст и читаемость текста и кнопок (WCAG 2.1 AA по возможности).
