Добро пожаловать в WEU AI

WEU AI — веб-платформа для DevOps-команд. В одном интерфейсе доступны агенты, SSH-серверы, задачи и база знаний.

check_circle
Платформа работает в браузере. Дополнительные desktop-клиенты не требуются; достаточно один раз развернуть окружение.
chat

Чат с ИИ

Gemini и Grok. Стриминг ответов, загрузка файлов, история сессий.

smart_toy

Агенты

Ralph, Cursor, Claude Code, ReAct. Создавай воркфлоу, запускай по расписанию.

dns

Серверы / SSH

Браузерный xterm.js-терминал, мульти-вкладки, AES-256 шифрование паролей.

task_alt

Задачи

Jira-подобный трекер. Проекты, спринты, AI-анализ, делегирование ИИ.

library_books

База знаний

RAG на Qdrant. Загружай документы — ИИ использует их при ответах.

extension

MCP / Skills

Подключай внешние инструменты через Model Context Protocol.

Установка WEU AI

Три способа запустить платформу: Docker (рекомендуется), локально с PostgreSQL в Docker, или полностью локально без Docker.

info
Порт по умолчанию: 9000. Меняется через переменную DJANGO_PORT в .env.

Требования

  • check_circle Docker Desktop 24+ или Docker Engine 24+
  • check_circle Docker Compose v2 (встроен в Docker Desktop)
  • check_circle API-ключ Gemini или Grok
  • check_circle 2 GB свободного места
1

Клонируй репозиторий

Склонируй проект в удобную директорию.

git clone https://github.com/your-org/web_rA.git
cd web_rA
2

Создай файл окружения

Скопируй пример и заполни обязательные переменные.

cp .env.example .env
nano .env   # или любой текстовый редактор

Минимальный .env:

# Минимальная конфигурация
GEMINI_API_KEY=ваш_ключ_gemini
SECRET_KEY=случайная_строка_50+_символов
MASTER_PASSWORD=пароль_для_расшифровки_серверных_кредов
POSTGRES_DB=weu_ai
POSTGRES_USER=weu
POSTGRES_PASSWORD=сложный_пароль
3

Собери и запусти

Docker Compose поднимет web, postgres, qdrant и redis.

docker compose up --build

# Или в фоне:
docker compose up --build -d
docker compose logs -f web
4

Создай администратора

После первого запуска создай суперпользователя.

docker exec -it weu-web python manage.py createsuperuser
5

Открой браузер

Открой http://localhost:9000/welcome/ и выполни вход.

Конфигурация платформы

Настройка через файл .env и .model_config.json. Все параметры опциональны, кроме API-ключа и SECRET_KEY.

Файл .env — все переменные

# ════════ LLM ════════
GEMINI_API_KEY=AIza...         # Google Gemini
GROK_API_KEY=xai-...           # xAI Grok (опционально)

# ════════ Django ════════
SECRET_KEY=django-insecure-...  # обязательно для prod
DEBUG=0                          # 1 в dev, 0 в prod
ALLOWED_HOSTS=yourdomain.com,localhost
DJANGO_PORT=9000                 # порт по умолчанию

# ════════ PostgreSQL ════════
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=weu_ai
POSTGRES_USER=weu
POSTGRES_PASSWORD=...

# ════════ Qdrant (RAG) ════════
QDRANT_URL=http://localhost:6333 # если не задан — InMemory

# ════════ Безопасность ════════
MASTER_PASSWORD=...              # расшифровка SSH-кредов

# ════════ Сборка ════════
WEU_BUILD=mini                   # mini | full (с PyTorch)

Конфигурация моделей (.model_config.json)

Файл в корне проекта. Изменяется через UI (Настройки → Модели) или вручную.

{

  "agent_model_gemini": "gemini-2.0-flash-exp",
  "rag_model_gemini":   "gemini-1.5-flash",
  "chat_model_grok":    "grok-beta",
  "agent_model_grok":   "grok-beta",
  "default_provider":   "gemini"

Модель агентов Cursor всегда принудительно auto и не изменяется через UI — это ограничение Cursor CLI.

Агенты и воркфлоу

Раздел предназначен для настройки workflow: выбор runtime, запуск шагов и просмотр логов в реальном времени. Каждый агент работает в изолированном процессе.

Типы агентов (runtime)

RuntimeТипКогда использовать
Ralph Итеративный LLM DevOps задачи с несколькими шагами: проверка серверов, анализ логов, деплой
Cursor CLI (Cursor AI) Задачи с изменением кода, рефакторинг, написание скриптов
Claude Code CLI (Anthropic) Сложные задачи с файловой системой, MCP-инструменты
ReAct Внутренний Цепочка инструментов (SSH + поиск + задачи) с прозрачным логом
Simple / Complex Внутренний Одиночные запросы к LLM без инструментов

Воркфлоу

Воркфлоу — это именованная последовательность шагов. Каждый шаг — отдельный промпт или команда. Запускаются вручную, по webhook или из задачи.

1

Создайте workflow

Откройте: Агенты → Создать workflow, затем выберите профиль агента и runtime.

2

Добавьте шаги

Каждый шаг задаётся как промпт или команда. Шаги выполняются последовательно, результат предыдущего шага доступен следующему.

3

Запустите выполнение

Кнопка ▶ Play запускает workflow; логи отображаются в реальном времени. Выполнение можно остановить в любой момент.

Серверы и SSH

Раздел для управления SSH-серверами: браузерный терминал xterm.js, работа с несколькими вкладками и шифрование учётных данных.

  • check_circleБраузерный терминал — xterm.js через WebSocket, полная совместимость
  • check_circleНесколько вкладок — открывай несколько серверов одновременно
  • check_circleAES-256 шифрование — пароли расшифровываются только в момент подключения
  • check_circleДоступ агентов — агент может подключаться по SSH и выполнять команды в рамках сценария
  • check_circleФильтрация опасных команд — rm -rf, mkfs, shutdown блокируются
  • check_circleГруппировка по тегам — prod / dev / staging, фильтрация в списке

Добавление сервера

1

Серверы → Добавить

Заполни: имя, хост, порт (22), логин, пароль или приватный ключ.

2

Проверьте соединение

Кнопка "Тест соединения" выполняет проверку SSH без хранения пароля в открытом виде.

3

Откройте терминал

Кнопка "Terminal" рядом с сервером открывает вкладку с браузерным терминалом.

Skills и MCP

Model Context Protocol (MCP) — стандарт подключения внешних инструментов к ИИ. Через него агенты получают доступ к сторонним API, базам данных и сервисам.

В разделе Skills / MCP находится каталог доступных серверов. Подключённые MCP-серверы автоматически добавляют свои инструменты в пул агента.

Встроенный MCP-сервер

В платформу входит встроенный MCP-сервер (mcp_server.py), который предоставляет агентам Claude Code доступ к следующим инструментам:

  • server_execute — выполнение команд на SSH-серверах пользователя
  • servers_list — список зарегистрированных серверов
info
Конфигурация MCP для агента формируется при запуске. Подключённые MCP-серверы автоматически добавляют доступные инструменты в пул агента.

Архитектура платформы

WEU AI построен на Django ASGI с модульной архитектурой. Компоненты можно конфигурировать и развивать независимо.

Пользователь (браузер)
       │  HTTP / WebSocket
       ▼
Django ASGI (Daphne)  ←  ALLOWED_HOSTS, CORS
       │
       ├─ Чат / Orchestrator  →  UnifiedOrchestrator
       │         │                    ├─ LLM Provider (Gemini/Grok)
       │         │                    ├─ Tool Manager
       │         │                    └─ RAG Engine (Qdrant/InMemory)
       │         │
       ├─ Агенты Hub  →  CLI Runtime
       │                      ├─ Ralph (internal LLM loop)
       │                      ├─ Cursor CLI  (subprocess)
       │                      └─ Claude Code CLI (subprocess)
       │
       ├─ Серверы SSH  →  Channels WebSocket → xterm.js
       │
       └─ Задачи / RAG / Пароли  →  Django ORM → Postgres/SQLite

Структура директорий

web_rA/
├── app/                   # Core AI/orchestration layer
│   ├── agents/           # Agent implementations
│   ├── core/             # LLM, orchestrator, model config
│   ├── rag/              # RAG engine (Qdrant / InMemory)
│   ├── tools/            # SSH, filesystem, web tools
│   └── mcp/              # MCP client
├── core_ui/              # Main web interface
│   ├── templates/        # HTML-шаблоны
│   └── static/           # CSS, JS, images
├── agent_hub/            # Agent profiles, workflows, logs
├── tasks/                # Task management + Jira integration
├── servers/              # SSH server management
├── passwords/            # Password manager (AES-256)
├── web_ui/               # Django project settings
├── mcp_server.py         # Standalone MCP server для Claude Code
└── manage.py

Безопасность

Раздел описывает механизмы безопасности платформы: шифрование данных, фильтрацию опасных команд и модель разграничения доступа.

Шифрование данных

  • check_circleПароли и SSH-ключи серверов шифруются AES-256 с использованием MASTER_PASSWORD
  • check_circleРасшифровка происходит только в момент подключения — в RAM, нигде не сохраняется открытым текстом
  • check_circleMASTER_PASSWORD никогда не хранится в БД — только в переменной окружения

Блокировка опасных команд

Перед выполнением SSH-команд применяется проверка по списку опасных паттернов (app/tools/safety.py). Ниже приведены примеры блокируемых команд:

# Заблокированные паттерны:
rm -rf /           # удаление корня
mkfs               # форматирование диска
dd if=             # прямая запись на диск
shutdown / reboot  # остановка системы
systemctl stop/disable/mask  # остановка сервисов
truncate -s 0      # обнуление файлов

  • check_circleПрава на серверы, воркфлоу и задачи управляются через группы и разрешения Django
